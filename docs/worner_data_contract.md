# Wörner confirmation data contract

The confirmation benchmark consumes the normalized table generated by
`scripts/normalize_worner.py` from the checksum-verified Zenodo archive.

## Canonical columns

| Column | Role | Rule |
|---|---|---|
| `timestamp` | required | ISO timestamp of the first sample in a measurement file |
| `batch_id` | required | consecutive six-day temporal window |
| `location_id` | required | constant `laboratory_e_nose` |
| `gas_id` | required | `Diacetyl` or `Phenylethanol` |
| `target` | required | numeric concentration in ppm |
| `target_unit` | metadata | `ppm` |
| `day_id`, `day_ordinal` | metadata | source day folder and its temporal order |
| `date_source` | metadata | source date string |
| `record_id`, `source_file` | metadata | deterministic source identity |
| `row_in_batch` | metadata | order after temporal sorting; excluded from features |

All columns after metadata are numeric sensor features. There are 252 features
as defined in `docs/worner_schema_audit.md`. No feature may use the target,
filename, day/window label, or future observations.

## Exclusions and missingness

Ethanol files (232) are excluded because 5% v/v ethanol is a diluent/blank and
does not provide a varying analyte concentration target. Any non-finite feature
vector is a normalization failure, not an imputation opportunity. The archive
checksum must match before normalization.

## Confirmation split

Use six-day windows as the primary temporal unit, with source windows preceding
each target window. Freeze the target holdout before selecting references. Use
the nested reference budgets 0, 2, 5, 10, 20, and 50 labeled target-window
observations, capped by the available reference pool. Alternative window widths
and a feature-table sensitivity analysis are mandatory and must be reported as
sensitivity analyses, not silently pooled with the primary result.
